# Лабораторна робота: Проєктування ПЗ (Варіант 17 — Трекер навчання)

## 1. Планування
**Мета:** створити простий та зручний застосунок «Трекер навчання», який допомагає студентам систематизувати навчальний процес і відстежувати свій прогрес за дисциплінами. Користувач повинен мати можливість додавати навчальні завдання або пройдені лекції з прив’язкою до конкретного курсу, відзначати їх виконання та бачити загальний прогрес навчання.

## 2. Аналіз вимог (User stories)
1. Як студент, я хочу додавати нове завдання або лекцію із зазначенням назви курсу, щоб фіксувати все, що потрібно опрацювати. ✅ **(Must have)**
2. Як студент, я хочу відзначати завдання чи лекцію як виконані, щоб бачити свій реальний прогрес по курсу. ✅ **(Must have)**
3. Як студент, я хочу переглядати список завдань за конкретним курсом або всі разом, щоб зручно планувати свій час.
4. Як студент, я хочу видаляти помилково додані або неактуальні записи, щоб підтримувати порядок у трекері.
5. Як студент, я хочу бачити відсоток виконаних завдань, щоб оцінювати готовність до сесії.

**Опис екранів прототипу:**
* **Екран 1 (Головна — Список курсів і завдань):** зверху відображається шкала загального прогресу (наприклад, *«Виконано 4 з 8 завдань — 50%»*), нижче — список завдань із назвою курсу, чекбоксом виконання та кнопкою видалення, а внизу — кнопка «+ Додати завдання».
* **Екран 2 (Ключова функція — Додавання навчального завдання):** містить випадаючий список або поле для вибору курсу (наприклад, *«Інженерія ПЗ»*, *«Бази даних»*), поле введення теми лекції чи лабораторної роботи та кнопку «Зберегти».

## 4. Реалізація (Псевдокод)
Алгоритм роботи ключової функції — додавання нового навчального завдання до трекера:

```text
studyTasks = []

function addStudyTask(courseName, taskTitle):
    if courseName is empty or taskTitle is empty:
        return "Error: Course name and task title cannot be empty"
    
    newTask = {
        id: generateUniqueId(),
        course: courseName,
        title: taskTitle,
        isCompleted: false
    }
    
    studyTasks.add(newTask)
    updateProgressIndicator(studyTasks)
    return "Study task added successfully"
```

## 5. Тестування
1. **Додавання завдання з коректними даними (курс: *«Інженерія ПЗ»*, назва: *«Лабораторна робота №1»*)** → запис з’являється у списку зі статусом «Не виконано», а лічильник завдань оновлюється.
2. **Спроба зберегти завдання з порожньою назвою або без вказання курсу** → система блокує додавання і виводить повідомлення про помилку.
3. **Позначення завдання як виконаного (натискання чекбокса)** → статус змінюється на «Виконано», а відсоток загального прогресу автоматично перераховується.

## 6. Висновки
Для розробки цього проєкту найкраще підходить модель **Agile** із короткими ітераціями. Вона дозволяє швидко випустити базову версію (MVP) для обліку лекцій і завдань, а далі поступово додавати нові можливості (дедлайни, нагадування, фільтрацію за семестрами, оцінки) на основі фідбеку студентів. Модель Waterfall є занадто повільною для невеликого продукту, а Spiral — надлишковою через відсутність високих технічних ризиків.
